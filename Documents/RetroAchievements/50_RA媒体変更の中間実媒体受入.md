## 2. 最初に確認する基本動作

### A. RA OFFでゲーム中の交換（GU-01）

1. RA mode OFFで、従来使っていた二Drive構成のゲームを起動する。
2. ゲームが交換を要求した場面で、Drive 1だけ、Drive 2だけの交換をそれぞれ行う。使用ゲームにない操作はNOT RUNとする。
3. bank切替とEject→再挿入を確認する。複数bankを持つ媒体ならbank 0/1以外も一つ使う。
4. 二Drive同時指定が可能な媒体・入口でも構成を作る。

期待: 指定したDriveとbankを使用でき、単独操作で他Driveが変わらない。RA待ちで妨げられず、ゲームが実際に読み込み・続行できる。通常のメニュー交換で意図しないresetが起きない。

### B. RA ONで非対応ゲームを交換する（GU-02／04）

1. RA ONで非対応ゲームをDrive 1から起動する。RAはOfflineでもよい。
2. Aと同じ代表的な交換とEject→再挿入を行う。
3. 少なくとも一回、mouseでDriveメニューを操作し、もう一回はkeyboardで操作する。

期待: RA非対応であることを理由にmount／Ejectを拒否しない。Offline後も繰り返し交換でき、ゲームが続行できる。

AまたはBで「以前mountできた媒体がmountできない」場合は、そのケースをFAILとして先に報告する。以後の試験を無理に進めなくてよい。

## 3. C. 今回変更した入口とreset（GU-04）

RA対応ゲームを使い、まずHardcoreで次を確認する。その後Casualで二行M3Uまたは二Drive指定を一回繰り返す。
ファイル形式ごとに別のゲームを使ってもよい。

| 操作 | 期待する結果 |
|---|---|
| 新規起動として別D88二枚をmenuの二Drive指定でOpen | 指定した両Drive構成で起動。識別待ちが見える場合、Drive 1だけ先に入った構成を残さない |
| ゲーム起動中に、同じゲームの二行M3UをD&D | M3Uで指定したpath／bankの両Driveへ変更してreset。Busyを理由に二枚目だけ失敗しない |
| Drive 1が既にM3Uと同じ媒体の状態でも同じD&D | Drive 2も指定どおり入り、完了後にresetする |
| 一行M3UをD&D | Drive 1を指定媒体へ変更し、Drive 2を空にしてresetする |
| multi-bank D88を直接D&D | Drive 1はbank 0、Drive 2はbank 1でresetする |
| 単一bank D88を直接D&D | Drive 1に挿入、Drive 2は空でresetする |
| 成功した二Drive構成をLibraryのSTARTから起動 | 保存されたDrive／bank構成で新規起動する |

D&Dは必ずresetする。自動試験では一回を数えている。実働ではbootが不自然に二度繰り返されないこと、交換後にゲームが起動・読み込みできることを確認する。
通常のゲーム内交換はD&Dとは別に、メニューの単独Open／bank切替で確認する。同じゲームの通常交換に余分なresetを追加しない。

RA検証待ちが自然に見える場合だけ、二Drive要求中の競合EjectがBusyとなり、元の要求の完了を壊さないことも確認できる。
待ち時間を作るための回線切断や高速な連打は不要。このタイミングの制御と失敗注入は自動試験で行っている。

3. RAの識別が再開し、対応ゲームとして動作することを確認する。
