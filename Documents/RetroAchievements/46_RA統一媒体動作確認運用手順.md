# RA統一媒体 動作確認運用手順

基準日: 2026-09-02
状態: **現行運用規範**

本書は [45_RA統一媒体状態仕様と検証基準.md](45_RA統一媒体状態仕様と検証基準.md) の
AM-01〜AM-12を確認する唯一の運用手順である。旧
[44_動作確認運用手順.md](44_動作確認運用手順.md) は履歴資料であり、ケース番号と
Casual／Hardcore別の媒体手順を再利用しない。

## 1. 三層の確認

| 層 | 担当 | 確認対象 |
|---|---|---|
| 自動 | Codex／CI | RA有効build、policy、transaction、service、入口正規化 |
| GUI・実受入 | ユーザー | 実buildのmenu、mouse／keyboard、Drive表示、mount結果、実アカウント、Keychain、実ネットワーク断 |

自動成功だけでGUI・実受入成功を宣言しない。
ユーザー管理のD88、state、設定、RA DBを削除・移動・置換しない。

## 2. 自動検証

RA有効buildだけを使用する。RA無効buildは対象外であり、Normal回帰は同じbuild内で
RA mode OFFにして行う。

```sh
scripts/verify_ra.sh --scope disk
scripts/verify_ra.sh --scope full
```

媒体状態機械、transaction、session、Hardcore操作ガードを変更した場合は`--scope full`を必須とする。
reportのPASSは自動層だけを意味する。`git diff --check`も実行する。

| AM | 自動確認 |
|---|---|
| 01, 02 | `ra_media_change_policy_test`、`ra_multi_image_policy_test`、`ra_media_request_integration_test`、`ra_media_state_matrix_test` |
| 03〜07 | policy、transaction、serviceのfake通信ケース。AM-03は`Offline → 登録Drive 1 → reset → Starting`を入口ごとに確認する |
| 08 | `ra_service_test` の永続outbox・再送ケース |
| 09, 12 | transactionのbusy・逐次commit・rollbackケース、`ra_media_state_matrix_test` |
| 10 | `ra_session_policy_test`、frame callback、menu policyケース |
| 11 | 媒体要求統合テスト、`ra_media_state_matrix_test`、CLI/menu routingテスト。mount後のresetとDrive 1再識別まで比較する |

## 3. ユーザーGUI受入

実行前に起動する`.app`の絶対パス、RA mode、到達性、使用媒体、Drive 1/2の期待構成を記録する。
Keychainのpasswordまたは許可ダイアログを含め、GUI操作と結果判断はユーザーが行う。

2026-09-20のユーザー指示により、通常のGUI操作と観測はComputer Useへ、Androidでは
android-cliスキルへ委任する。Keychain等の保護された入力・許可、実回線切断はユーザー担当を維持する。

| ケース | 操作 | 合格条件 |
|---|---|---|
| GU-01 | RA mode OFFでDrive 1/2 Open、bank切替、Eject | 対象Driveだけが変わり、待機・RA通信がない |
| GU-02 | RA ONでDrive 1の別hashをOpenとbank切替で実施 | 同じ媒体判定・表示になる |
| GU-03 | RA ON ActiveDisconnected相当のtest hookがある場合、検証済みDrive 2を変更 | active mediaを変えずmountする |
| GU-04 | Open Both、Library、M3U、CLI/D&Dの代表経路 | 同じ二Drive構成を作り、半端な構成を残さない。未登録Drive 1でOffline後に登録Drive 1へ交換した場合、reset後に全入口でRA識別する |
| GU-05 | HardcoreのStartingとActiveDisconnectedでFull Speed、手動Save | Full Speedは拒否、手動Saveは許可 |

mouseとkeyboardの双方で、変更したmenu経路を少なくとも一つずつ確認する。RA通信だけを遮断する
明示的test hookがない場合、GU-03は`NOT RUN`として実ネットワーク断を代替しない。

## 4. ユーザー実ネットワーク受入

実ネットワーク断はユーザーが単独で操作する。切断前にbuild path、開始状態、操作、期待結果、
記録事項、XM8を閉じるかどうかを渡す。firewall、hosts、VPNなどを即席のtest hookとして変更しない。

1. RA ONで対象ゲームを検証済みまで起動する。
2. 通信を切断し、実績解除、Drive 2の検証済み媒体交換、未検証またはDrive 1の媒体交換を順に行う。
3. 実績評価・Hardcore禁止操作が切断中も継続すること、検証済みDrive 2だけがsessionを維持すること、
   その他はOfflineでmountすることを記録する。
4. 接続を復旧し、outboxが成功または既解除応答まで再送されることを確認する。

## 5. 完了報告

```text
自動テスト:
- RA有効build: PASS / FAIL
- verify_ra.sh --scope full: PASS / FAIL
- report: /absolute/path
- git diff --check: PASS / FAIL

ユーザーGUI受入:
- GU-xx: PASS / FAIL / NOT RUN
- build: /absolute/path/to/xm8.app

ユーザー実受入:
- 実ネットワーク断・outbox: PASS / FAIL / PENDING

残件:
- なし、または具体的な未確認条件
```

## 6. OS横断の反復確認（2026-09-20追加）

[共通実受入ツール](../../scripts/ra_acceptance_README.md)と
[シナリオ定義](../../scripts/ra_acceptance_cases.json)を使用できる。
実行方法は前者へ集約する。シナリオは45・46・50を根拠とし、新しい媒体仕様を追加しない。

- OS・端末・build SHA-256ごとに新しいrunを作り、旧結果を流用しない。
- Computer Use／Android CLIは操作・観測を担当する。画面や記録を保存し、観測できない項目は保留する。
- TypeSafeは明示的に選んだ観測文の補助分類だけを行い、PASS判定を所有しない。
- 自動層のreportとGUI台帳は分離する。台帳のテスト成功もXM8の受入ではない。
- AndroidのD&D／CLI等が未提供なら未実施理由を記録し、SAF等の別操作へ暗黙に置換しない。
- 最初のシナリオ集だけで全プラットフォーム受入完了としない。各OS固有の残件も従来文書で管理する。
