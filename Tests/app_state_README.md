# 通常セーブステートの統合テスト

`app_state_test` はRA有効ビルド内の **RA mode OFF** を対象に、実際の
`App::Save` / `App::Load`、Setting、DiskManager、TapeManager、FILEIO、VMを使用します。
VMのシリアライズ・復元は置き換えていません。ROMがない状態のVMを使うため、
実ゲームが続きから動くことを確認するGUI受入とは区別してください。

確認項目:

- 設定、両ドライブのファイル・bank、テープ再生状態、VMのRAMを含む保存・復元。
- 復元されたカーソル・数字キー設定が、実際のInputの出力に反映されること。
- 媒体あり／なしの復元、通常スロットと自動保存用スロット0の独立性。
  スロット0も公開Save/Loadを呼びますが、起動・終了時の自動呼び出しは対象外です。
- 読み込み先なし、保存先がディレクトリで開けない場合の失敗。
- VMデータ書き込み途中のshort write、クローズ時の失敗をSaveが成功扱いしないこと。
- 新規保存・既存スロット上書きの失敗後に再保存でき、そのデータを復元できること。
- 設定領域の途中切れ・不正version、VMの不正version・末尾途中切れをLoadが失敗扱いすること。
- 成功・失敗後のVM semaphoreの釣り合いと、正常な保存データからの再読み込み。
- 保存・復元が生成した入力媒体を書き換えないこと。

## 隔離と失敗の再現

一意な一時ディレクトリにD88、テープ、設定、stateを生成します。
`Setting::Init`や`App::Init`は呼ばず、テスト用friendで依存関係と保存先を設定します。
ROM探索も同じ一時ディレクトリに限定し、ユーザーの設定、ROM、媒体、Keychainを使用しません。
描画用にはメモリ上のソフトキーバッファ、音声にはSDL dummy driverを使用します。

`app_state_fileio.cpp`は変更していない本番の`Source/UI/fileio.cpp`を取り込み、
その翻訳単位の`SDL_RWFromFile`呼び出しだけをテスト専用アダプターへ置き換えます。
通常は実SDLファイルI/Oへ委譲します。指定したstateの書き込みだけに失敗を注入するため、
OSの権限、空き容量、`/dev/full`に依存せず、macOS・Windows・Linuxで同じ条件を検証できます。
想定したI/O異常中のSDL assertionは、Debugビルドでもダイアログを開かず無視します。
想定外のassertionはテスト失敗です。本番のファイルI/Oへのフック追加はありません。

## 現行処理の制約

- 通常Saveは対象ファイルを直接上書きします。失敗した同一スロットの旧データ保持は
  保証されません。テストは失敗通知、他スロットの保持と再試行を確認し、原子的保存は追加しません。
- 設定領域での早期拒否はVMを置き換えませんが、VM領域で失敗すると設定・媒体・VMへ
  一部反映済みの場合があります。失敗時の全面的なロールバックは保証せず、
  正常なstateによる復旧を確認します。
- 任意の破損バイト列の安全性、媒体ファイルが消えた場合、音声周波数変更、
  RA mode ONのstate、起動・終了のGUI経路は対象外です。

エミュレーションコアとstate形式は変更していません。

```sh
scripts/verify_ra.sh --scope state
```

CMakeの`BUILD_TESTING=ON`かつRA有効時にCTestへ登録されるため、既存の
macOS・Windows x64・Linux x86_64/arm64のCTest CIでも実行されます。
