# 設定の保存・復元テスト

`setting_persistence_test` は実際の `Setting::SaveSetting` / `LoadSetting` と
`FILEIO` を使い、設定ファイルの読み書きをウィンドウなしで検証します。
`Setting::Init` / `Deinit` は呼ばず、ユーザーの設定・ROM・stateには触れません。
テスト用のファイルは一時領域へ作成し、正常終了時に削除します。

確認する内容:

- システム・画面・音声・入力・スロットなど全保存項目の往復一致。
- 現行形式159バイトの全切断位置（空ファイル、部分ヘッダーを含む）。
- 未対応バージョン、不正なbool表現、選択番号、非正の画面幅・音声値。
- 失敗時のUI設定と共有configの保持、成功時の無関係なconfig項目の保持。
- 旧9形式の読み込みと末尾欠落、旧形式にない項目の初期値。
- 既存の回転・スケーリング補正、セーブステート後続データを読み越さないこと。

ファイルのバージョン・サイズ・フィールド位置は既存形式の互換性を確認する固定値です。
保存形式やバージョン番号、エミュレーションコアは変更していません。
既存形式にはチェックサムがないため、有効な値に化ける任意のビット反転までを検出する
テストではありません。

RA有効ビルドで実行します:

```sh
scripts/verify_ra.sh --scope state
```

全回帰は `--scope full`。CMakeの `BUILD_TESTING=ON` で登録されるため、
既存のLinux・macOS・Windows x64の全CTestジョブでも自動実行されます。
Androidは共通コードのビルド確認であり、このC++テストの端末上実行は含みません。
