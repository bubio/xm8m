# 画面座標・メニュー操作のCIテスト

`ui_test`は実際のVideo、Menu、MenuList、MenuItem、Input、SettingとAppを使用します。
メニューのコマンド受信をモックせず、設定の変更と親メニューへの復帰まで確認します。

- 1倍・2倍、横長・縦長の余白、描画領域の内外と末尾境界。
- ステータス行ありのゲーム座標、専用ステータス座標、メニューの描画座標の対応。
- 大きさ0の描画領域の拒否、正規化されたタッチ座標（微小な負数・範囲外・NaNの拒否）。
- 縦画面の下側パネルに対するメニュー・ソフトキーの座標変換。
  このケースはテスト用friendで矩形を与え、Android固有のパネル配置計算とは区別します。
- キーボードでのサブメニュー選択、チェック変更、上下・Home・Endとスクロール。
- Enter・Escapeのリピート抑制、Escape・右クリックによる親メニューへの復帰。
- マウス押下・解放でのチェック変更と、領域外解放によるキャンセル。
- タッチによる設定変更、項目から領域外へ移動した解放のキャンセル、領域外タップのBack。
- スライダーのキーボード操作、最小・最大値、F11による実Appのメニュー終了。

SDLの音声にはdummy driver、描画にはメモリ上のバッファを使い、ウィンドウを開きません。
App::InitとSetting::Initを呼ばず、ROM探索と設定保存先を一意なテスト用ディレクトリへ隔離します。
MenuListの時計だけをテスト翻訳単位で置き換えるため、待機時間や実行速度に依存しません。
エミュレーションコアは変更していません。

回帰テストで確認したUIの修正:

- 座標は対応する描画矩形から変換し、ゲーム400行と専用ステータス18行を分ける。
  メニューは実際に描かれる400行へ対応させる。
- 整数除算前に境界判定し、拡大時の余白の負の1ピクセルを画面内として扱わない。
- 変換に失敗したタッチ解放で、初期化された座標から先頭項目を選択しない。

```sh
scripts/verify_ra.sh --scope ui
```

RA有効のCTestへ登録し、既存のmacOS・Windows x64・Linux x86_64/arm64 CIで実行します。
実画面の見え方、OSのイベント配送、IME・実入力機器、Androidの回転要求の実動作は対象外です。
自動テスト成功をGUI受入成功として扱いません。
