# 音声出力処理の自動テスト

`audio_test` は本番の `Source/UI/audio.cpp` を使用し、バッファの内容と残量、
SDLへ登録した実際の `CommonCallback` からの出力を検証します。
エミュレーションコア、ROM、ユーザー設定を使用しません。

確認項目:

- 読み込み・書き込みの末尾跨ぎ、末尾ちょうど、全容量の転送。
- 未読データを残した追加書き込みとステレオの順序。
- 満杯・一部だけ空き・容量を超える書き込みで、未読データを上書きしないこと。
- 空バッファ・不足時の無音出力と、補充した半分の容量／全容量を超える要求への対応。
- 不足後も残量が負にならず、次の書き込みと読み出しが正常に行えること。
- 初回Playの半分の無音補充、繰り返しPlayによるデータ保持。
- Stopの重複呼び出しと、停止後のPlayで古いデータがクリアされること。
- 再生・停止の反復、デバイスの一度だけの解放。
- 32bit入力から16bit出力への2/3変換とクリッピング。
- 空の書き込み、CommonCallbackへのnull/空要求、出力先の前後の境界。
- 44100 / 48000 / 55467 Hz、120msでのバッファ容量と出力。

## 決定的に実行する仕組み

テスト翻訳単位から本番のaudio.cppを取り込み、SDLのデバイス列挙・Open・Pause・Close
だけをテスト用の同期アダプターに置き換えます。SDLのメモリ確保とセマフォは実物です。
登録されたコールバックをテストから手動で呼ぶため、実デバイス、バックグラウンドの
音声スレッド、sleep、物理的な出力には依存しません。

折り返しを確実に発生させるケースでは8ステレオフレームの小さなバッファを使い、
別ケースで製品のサンプルレートを検証します。データは左右で異なる既知の値を使用します。
Audioの処理や残量計算をモックしたり、private状態を直接設定したりしていません。

## 不足時の修正

既存処理は不足時に半分の無音を補充した後も、要求された長さをそのまま読み出していました。
要求が補充量を超えると残量が負になり、さらに大きい要求では範囲外読み取りの可能性が
ありました。回帰テストで残量の異常を再現し、UI側Audio::Callbackを修正しています。
補充量を超えた要求の残りを無音で埋め、実際に消費する量を補充した残量内に制限します。
通常の不足時の半分の無音補充と、再生・停止の仕様は変更していません。

## 実行と対象外

```sh
scripts/verify_ra.sh --scope state
```

CMake/CTestとstateスコープに登録されるため、既存のmacOS・Windows x64・
Linux x86_64/arm64のCTest CIでも実行されます。検証はRA有効ビルドを使用します。

実際の聞こえ方、音切れ・遅延、OSのデバイス切り替え、音声スレッドとの競合、
実デバイスのOpen失敗、VMの音源生成の正しさは対象外です。
それらは実デバイス・GUIの確認や別の検証として扱います。
