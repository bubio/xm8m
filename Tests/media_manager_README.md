# 媒体マネージャーの自動テスト

`media_manager_test` はRA有効ビルドのRAモードOFFで、実際のTapeManager、DiskManager、App、FILEIO、VMを使用する。コアのソースは変更しない。

## 確認する内容

- テープの再生・録音への切り替え、ファイル名・ディレクトリ、繰り返し取り外し。
- Appの保存・復元による再生中・録音中・未装着状態の復元。
- USART出力信号から録音したバイト列の書き出しと、復元後の録音継続。
- 存在しない再生ファイル・録音先への切り替え失敗時に、現在の再生を保持。
- 事前確認後の録音ファイルopen失敗、事前確認close失敗の報告。
- 録音flushの短い書き込み、取り外し後の再録音と完全なデータ出力。
- ディスクの事前検査後のFDC open失敗を失敗として報告。
- 読み取り専用ディスクのopenフォールバックと保護状態、欠落ディスクの拒否。
- 元の再生用テープ・ディスクに変更がないこと。

FILEIOのコンパイル単位だけ、SDLファイルopen境界をテスト用アダプターに置換する。異常を注入するのは指定した生成ファイルだけで、成功する読み書きは実際のSDLとファイルシステムを使用する。読み取り専用状態はアダプターで再現し、OSの実行ユーザー権限に依存させない。

ROM探索先・設定・状態・媒体は固有の一時ディレクトリ内に限定する。実ROM、ユーザーの設定や媒体、ウィンドウ、CPUプログラム実行は使用しない。

## 実行

```sh
cmake --build <RA有効ビルド> --target media_manager_test
ctest --test-dir <RA有効ビルド> -C Release -R '^media_manager_test$' --output-on-failure
scripts/verify_ra.sh --scope disk --ra-build-dir <RA有効ビルド>
```

通常のCIの全CTest実行にも含まれる。

## 制約

録音flushの書き込み失敗は、現行コアの `close_tape()` が戻り値を持たないため、UIでの失敗通知までは検証しない。短い書き込みが実際に発生し、部分ファイルが残り、取り外しと再録音が可能になることを検証する。録音データの損失防止や原子的な保存を保証するテストではない。

SDLの実ウィンドウ操作、音声機器、Android SAF、実媒体の受入試験は対象外。GUI確認・VM・実機での確認済みとして扱わない。
